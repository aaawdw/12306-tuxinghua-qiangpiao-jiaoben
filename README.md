# 12306-图形化抢票脚本

归程 · Python 桌面购票助手。

当前主程序为 **Python + Tkinter + Python Playwright**。通过桌面窗口配置行程、乘客和车次，手动登录后自动查询、选择和提交，到待支付页停止，由你付款。日常启动不需要 npm 或单独安装 Node.js。

## 在 PyCharm 启动

1. 打开项目 `D:\workspace\ticket`。
2. Python 解释器选择本项目的 `.venv\Scripts\python.exe`（Python 3.12）。
3. 右键 `main.py` → **Run 'main'**，即可打开桌面窗口。

也可在 PyCharm 终端执行：

```powershell
.\.venv\Scripts\python.exe main.py
```

或双击 `start.cmd`。它现在会启动 Python 图形界面，不再启动原来的命令行菜单。

本机项目虚拟环境已安装所需依赖。换电脑或换解释器时执行：

```powershell
python -m ensurepip --upgrade
python -m pip install -r requirements.txt
python main.py
```

Tkinter 随本机 Python 提供。如果提示缺少 `_tkinter`，请安装带 Tcl/Tk 的完整 Python。默认使用已安装的 Chrome，可在界面改为 `msedge` 使用 Edge。选择 `chromium` 时需先执行 `python -m playwright install chromium`。

## 窗口里的操作顺序

1. **行程设置**：填写精确车站、乘车日期、开售日期及北京时间，以及查询间隔和时长。
2. **乘车人**：逐个添加 12306 已保存的乘客。姓名只保存在本机，不需要填写身份证号或密码。
3. **车次偏好**：输入车次、选择席别后点击添加。用上移 / 下移调整顺序；列表编号表示优先级。然后点击右上角 **保存配置**。已有的 `config.json` 会自动载入，也可导入旧版配置。
4. 在右侧选择模式，点击 **打开浏览器并开始**。
5. 如果连接真实网站，在浏览器中手动登录并检查未完成订单，然后回窗口点击 **已登录，继续**。
6. 待支付时声音提醒，窗口显示付款提示。请在浏览器核对并付款；完成后点击 **关闭浏览器会话**。

### 三种运行模式

| 模式 | 行为 |
|---|---|
| 网站查询演练（默认） | 查询真实网站，不点击预订、不提交订单 |
| 正式购票 | 等待配置的开售时间，查询匹配、选择乘客和席别、提交，到待支付页停止 |
| 本地模拟演练 | 使用内置虚构行程跑完整流程，无需填写配置、无需账号、不连接铁路网站 |

先用本地模拟熟悉流程，再进行网站查询演练。演练不会覆盖你的真实行程配置。

“立即开始”仅用于已开售的票，跳过定时等待。正式运行时如果开售时间已过去超过一分钟，窗口会提示你修改时间或勾选立即开始。乘车日期与起售日期是两个不同字段。

运行中配置锁定，防止参数中途变化。**暂停**在当前网站操作返回后的检查点生效，无法撤回已经发出的请求；**停止**结束自动操作并保留浏览器；**关闭浏览器会话**结束该次浏览器会话，之后可以修改配置并重新运行。关闭程序会同时关闭由它打开的浏览器。

## 当前能力与限制

- 支持成人票、学生票；多乘客不进行部分提交。儿童、其他特殊票种和同名乘客请在网站人工处理。
- 按车次＋席别列表从上到下匹配；仅选择明确配置的席别。网站订单选项名称无法精确匹配时停止并转人工。
- 在“车次偏好 → 座位偏好”选择自动分配、靠窗优先或靠过道优先。默认自动分配，无需逐个点击 A/B/C/D/F；位置偏好只在网站提供可识别选座时使用，不能保证最终位置。多人会按人数选择，位置不足时全部改为自动分配，避免部分选座卡住确认。
- 确认弹窗会等待网站倒计时结束、确认按钮可用后继续，到待支付页停止。界面显示“正在选座与确认”，日志区分选座、确认按钮等待和订票结果等待。
- 下铺优先 / 必须下铺：选择乘客与席别后停止，交给你在网站选铺和提交。不能保证具体座位位置。
- 中铺优先：在“车次偏好 → 卧铺”选择，遇到卧铺席别时，在确认弹窗按乘客人数申请中铺。没有中铺选项或账号未开通选铺时自动分配；网站余票不足也可能分配其他铺位。选铺按钮无法识别或数量未正确变化时转人工。此偏好不影响坐席。
- 候补：达到查询时限后提醒你在网站人工提交并支付预付款，当前没有自动候补提交。
- 验证码、扫码核验、登录失效、未知页面或弹窗会停止自动操作并提示你处理，不绕过网站核验。
- 默认查询间隔 5 秒，可设 0.1–60 秒；间隔从上一轮查询完成后计算，实际周期还包括网站响应和页面处理时间。始终串行查询，不并发堆积请求。网站限流时停止；普通查询异常最多重试两次，分别等待至少 10 秒和 20 秒。
- 定时运行会在开售前 5 秒检查查询页，到设定时间立即首查。“开售后 30 秒快速查询”默认开启，这段时间每轮完成后等待不超过 1 秒；若配置为 0.1 秒则仍为 0.1 秒。之后恢复配置间隔。“立即开始”不使用定时快速阶段。日志显示本机首查启动偏差；这不是服务器收到请求或完成下单的时间，无法保证瞬间提交成功。
- 查询后等待本轮结果表更新，并设置超时；空结果不会复用旧余票。启动日志显示本次实际使用的间隔和卧铺偏好。修改程序或配置文件后请退出旧助手再启动，避免旧窗口保存旧设置。
- 正式购票不能保证抢到票，也不能获得网站优先权。需核实对应车站起售时间，并保持电脑联网、唤醒、时间准确。

**已验证本地模拟完整流程和界面操作；真实账号登录后的乘客确认页与付款页仍需联调。程序遇到无法可靠识别的页面会转人工，不能将模拟测试等同于真实抢票成功。**

若已经看到乘车人和“提交订单”，旧版仍报“未能进入乘客确认页”，请退出旧程序后重新运行 `main.py`。新版检查实际乘客选框，兼容外层名单容器高度为零的布局，并从列车信息区域核对行程；切换票种后再选席别，避免网站重建选项导致席别被重置。若名单未加载，会明确提示“已进入乘客确认页，但乘车人名单尚未加载”。重试前仍需检查网站未完成订单。

新版还修正了含中文的乘客选框 ID 匹配，并在查询前、查询异常后检查页面阶段：如果已进入乘客页或确认弹窗，就停止查询，交由你处理当前订单，避免重新预订。查询按钮暂时不可用时先等待加载；查询重试日志会区分响应超时和结果读取失败。已停止的旧会话不会自动接管或重新提交现有弹窗。

## 本机文件与恢复

- `config.json`：本机行程配置，兼容旧版格式。保存时先校验，再原子替换；错误配置不会覆盖原文件。
- `.local/browser-profile`：浏览器登录会话，与旧版兼容。不要分享这个目录。
- `.local/attempts/`：提交前持久化记录，与旧版共用，迁移不会重置重复提交保护。本地记录不代表已出票。提交后超时不会自动重提或取消。
- `.local/run.lock`：阻止同时运行多个实例。旧版也使用该锁。

已有提交记录时，正式购票仍会打开浏览器。登录后点击“已登录，继续”，助手会显示“请核对上次订单”。在 12306 检查本行程的未完成订单、已支付/已出票订单及排队状态；如果确实没有订单且需要重新尝试，点击“已核对无订单，继续”并确认。助手只把当前行程记录移动到 `.local/attempts/archive/`，保留原始内容，再开始查询。其他行程记录不受影响。关闭、停止或未确认时保留记录，不自动重新提交。

如果异常退出留下 `.local/run.lock`，先检查旧程序已退出、浏览器已关闭，再人工移走这一个残留锁文件。正常运行中不要删除锁和提交记录。单纯更换车次偏好不会绕过同一行程的提交保护。

旧版 Node.js 源码暂时保留用于迁移参考，说明归档在 `docs/README-node.md`。不要同时启动两个版本。

## 开发与检查

```powershell
python -m compileall -q main.py ticket_app
python -m unittest discover -s tests -p "test_*.py" -v
```

浏览器测试使用本机 Chrome 和纯本地模拟站点。GUI 测试需要可用的桌面环境。

| 文件 | 职责 |
|---|---|
| `main.py` | PyCharm 运行入口 |
| `ticket_app/gui.py` | 图形界面、配置表单、状态和日志 |
| `ticket_app/layout.py` | 页面布局、行程摘要与列表显示 |
| `ticket_app/worker.py` | 后台线程与浏览器会话生命周期 |
| `ticket_app/browser.py` | 12306 页面适配 |
| `ticket_app/engine.py` | 定时查询、提交保护、停止逻辑 |
| `ticket_app/config.py` | 配置校验、持久化与优先级匹配 |
| `ticket_app/demo.py` | 纯 Python 本地模拟服务 |

设计使用 Python 标准库 Tkinter，后台线程中的独立 asyncio 循环执行 Playwright；线程之间通过消息队列通信，后台不直接操作 Tk 控件。Playwright 用法依据其[Python 文档](https://playwright.dev/python/docs/library)。
