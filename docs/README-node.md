# 旧版 Node.js 使用说明（归档）

你在程序打开的浏览器手动登录，程序按“车次＋席别”优先级查询、选择乘客并提交，到待支付页面后停止，由你核对并付款。只能减少本地操作耗时，不能保证有票或优先于其他用户。

**当前是首版：已实现本地模拟流程；真实乘客确认页需要登录后联调。验证码、未识别的页面、具体上下铺要求会交给你处理。候补目前提供提醒，不自动提交候补订单。**

## 使用

环境：Windows，Node.js 22+，Google Chrome（也可在配置中改为 `msedge`）。本目录原有 Python 项目不受影响。

双击 [start.cmd](start.cmd)，依次选择配置、演练、正式运行。首次安装或迁移电脑先执行 `npm install`。

菜单由 Node.js 显示，输入数字后按回车。若直接选择网站查询或正式运行但尚未配置，会先进入配置向导，完成后返回菜单。`npm start` 不会自动创建行程配置；首次使用需要先执行 `npm run setup`。

```powershell
npm run setup       # 问答式配置，生成本机 config.json
npm run demo        # 本地模拟完整流程，无需账号，不连接铁路网站
npm run dry-run     # 网站真实查询；不点击预订、不提交订单
npm start           # 正式运行：等待开售，匹配、填单、提交、待支付停止
```

正式运行前：核实车站对应的起售时间、乘车日期及乘客信息，检查 Windows 自动时间同步，保持电脑接电、唤醒、联网。建议提前 10–15 分钟启动并完成登录。程序不会自动修改系统时间或休眠设置。

在启动的浏览器中登录后，检查未完成订单，再回终端按回车。你可以在运行时输入 `p`、`r`、`s` 并回车，分别暂停、继续和停止。暂停不能撤回已经发到网站的请求。结果出现后浏览器保持打开；**付款或人工处理完成后**再在终端按回车退出。

起售时间已过去超过一分钟时会停止；如已核实信息、确实要现在开始：

```powershell
npm start -- --now
npm run dry-run -- --config D:\workspace\ticket\config.json
```

程序不在后台跨重启运行，不会在关闭终端后继续抢票，也不会自动付款。

## 配置

复制 `config.example.json` 为 `config.json` 后编辑，或运行配置向导。示例车次、乘客和日期都是占位示例，**不代表你的实际行程**。

| 字段 | 说明 |
|---|---|
| `from` / `to` | 精确车站名，例如北京西，不自动扩展到同城站 |
| `travelDate` | 乘车日期 `YYYY-MM-DD` |
| `saleAt` | 开售时间，含时区，如 `2026-09-17T09:15:00+08:00` |
| `passengers` | 已添加到 12306 的乘客姓名及成人票/学生票；同名乘客和儿童等特殊票种请人工购票 |
| `preferences` | 有序的车次和席别组合；同时有票时选择前面的组合 |
| `allowNoSeat` | 默认 false；true 允许确认页的无座提示；只想买无座需在 preferences 中明确选择无座 |
| `berth` | 不限/下铺优先/必须下铺。后两者会在填单后转人工选铺与提交 |
| `waitlist` | 提醒/关闭；达到查询时限后提示你人工选择候补和支付预付款 |
| `pollIntervalMs` | 查询完成后等待间隔，默认 5000 ms，最小 3000 ms；收到限制时停止 |
| `maxRunMinutes` | 起售后/立即模式下的最长查询时间；网站请求和排队等待可能超出这个查询时限 |
| `browser` | chrome / msedge / chromium；前两者使用本机浏览器，后者需 `npx playwright install chromium` |

支持二等座、一等座、商务座、硬座、硬卧、软卧等。网站合并展示的席别在订单页仍按**实际选项名称**核对；找不到精确对应选项就转人工，不能将“硬卧”和“二等卧”等默认为完全相同。下铺、靠窗等位置不保证。

## 异常与恢复

- 登录失效、滑块/验证码、乘客不匹配、行程变化、未知弹窗：停止自动操作，保持页面让你处理。
- 查询异常最多重试两次，间隔至少 10/20 秒；网站限流直接停止。
- 一旦开始提交，先落盘 `.local/attempts/<行程散列>.json`，再点击提交。提交后超时或失败，**不重试、不取消订单**；请检查网站排队状态和未完成订单。
- 重启遇到上述行程记录会阻止再次自动下单。只有在网站明确确认没有未完成订单、没有排队请求后，才人工将对应记录移走归档。修改车次偏好不会绕过该保护。程序保守地把提交前后不确定的失败都交给人工。
- `.local/run.lock` 防止同时启动多个实例。异常退出可能留下此文件；先关闭旧进程及其浏览器、确认订单状态后，才人工移走这个锁文件。不要在正常运行期间移走锁文件。
- 待支付页面识别不到或网站页面结构变化时，会报告需要人工接管，不会假报成功。付款期限以网站为准。

## 隐私与验证

`config.json` 和 `.local/browser-profile` 只放本机；浏览器资料含登录会话，不要分享或提交仓库。程序不保存密码，不主动导出 Cookie，不记录身份证号，不截取真实购票页面，不调用私有购票接口；通过正常网站页面操作。公开车站名称表来自 12306 `station_name.js`（2026-09-16 获取），新增车站可能需要更新。

```powershell
npm run check
npm test
```

测试涵盖优先级、库存数量、演练不下单、倒计时停止、提交前持久化、重启防重复、超时不重提，并在本机 Chrome 无头模式下对模拟站点验证从查询到待支付的完整流程及零支付点击。模拟测试不证明真实网站订票成功率；真实下单不作为测试手段。

公开查询页及脚本已核对的选择器集中在 `src/browser.ts`。登录后的乘客页和支付页适配仍需实际账户验证；若页面不符合预期，程序停止并交给人工。
